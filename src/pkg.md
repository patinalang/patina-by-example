# Packages

A package (`pkg`) is the basic unit of distribution for Patina libraries.
It's what you publish to the package manager like [Hex.pm][hex], what you specify in your
dependencies list, and what you reference when calling these dependencies.

## Naming conventions

For compatibility with the wider BEAM ecosystem, a package has three top-level names:

* **The package name itself**: this is the `snake_case` unique name you would publish
  to a package manager [Hex.pm][hex]. This is the only name you must set yourself.

* **The top-level BEAM module name**: even though Patina code references other packages by their
  _package name_, other members of the ecosystem have different conventions. For compatibility
  with Elixir, the BEAM modules generated by Patina are all named using `CamelCase`.

  The top-level BEAM module name is derived from the _package name_, e.g. `my_json_lib` package will
  use `MyJsonLib` by default. However, if you'd prefer it to be `MyJSONLib` instead, you will have
  to set it manually.

* **The OTP Application name**: this is what your [OTP application] - if any - will be called.
  Usually, you want to keep the default - which is set to the value of the _package name_.

## Package file

The `src/` directory of a Patina package must contain a source file named after the _package name_.
For example, for the `my_json_lib` package, the file name has to be `my_json_lib.pt`.

This is the _package file_. Patina compiler will start reading from that file, and, when it
encounters `mod` declarations, contents of the module files will be inserted in their place.
Files that are not referenced by the tree rooted in the _package file_ will not be read
or compiled.

[hex]: https://hex.pm
[OTP application]: https://www.erlang.org/doc/system/applications.html
